===== LUM-1490 footerData (the host->JS query channel) through the real bridge. The harness starts a real git repository in the child's cwd (`git_init`, branch `lum1490-main`) and an extension installs a custom footer that prints what `footerData` answered. Panel 1: `getGitBranch()`/`getAvailableProviderCount()` are queried from inside `render()` and return the driver's snapshot (`branch=lum1490-main`), not the hardcoded `undefined` this stub used to return. Panel 2: `! git checkout -b lum1490-side` moves HEAD outside the app and the footer follows without a restart, because the driver re-reads HEAD every tick and the shim fires the `onBranchChange` subscribers it registered the way upstream's own example does (`changes=1`). Panel 3: `/default-footer` restores the built-in footer, which shows `(lum1490-side)` - the same tracker feeds it, so the built-in footer follows an external checkout too (before LUM-1490 it was resolved once at startup). Panel 4: `git checkout --detach HEAD` then the custom footer again reads `branch=null`, upstream's answer for a detached HEAD / a session outside a repo.
